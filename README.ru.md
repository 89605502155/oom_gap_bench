# oom-gap-bench

Имитационный стенд к статье «Обзор методов учёта отказов процессов из-за нехватки оперативной памяти между точками мониторинга для переклассификации режима и пересчёта адаптивной системы управления KVM» (А. О. Ферубко, О. Д. Казаков, Вестник СПбГУПТД. Серия 4).

Стенд моделирует ситуацию, когда процесс пользователя быстро наращивает потребление памяти и завершается ядром гостевой ОС (OOM killer) между двумя точками мониторинга, а адаптивная система управления памятью (Ферубко, Казаков, Вестник РГРТУ, 2026, № 95) этого не замечает. Сравниваются шесть вариантов учёта таких отказов (M0–M5).

Это модель, а не KVM: в ней нет подкачки и замедления процессов при нехватке памяти. Числа показывают соотношение методов, а не поведение конкретной системы.

Английская версия: [README.md](README.md). Подробнее о вариантах: [docs/ru/methods.md](docs/ru/methods.md).

## Установка и запуск

Нужен Python 3.11–3.14. С [uv](https://docs.astral.sh/uv/):

```bash
uv venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
uv pip install -e ".[test]" pillow
python -m pytest                          # 10 тестов
python scripts/run_experiments.py         # 6 методов × 4 скорости × 20 прогонов, около 15 с
python scripts/make_figures.py            # рисунки 1 и 2
python scripts/pypi_audit.py --date 2026-11-10   # аудит пакетов PyPI (нужен интернет)
```

Зёрна генератора зафиксированы, результаты воспроизводятся полностью.

## Варианты

| Код | Вариант |
|---|---|
| M0 | исходный алгоритм: мгновенное значение, регрессия по 5 точкам, интервал 1–10 с по числу перераспределений |
| M1 | счётчик `oom_kill`: при приросте счётчика система переводится в нестабильный режим |
| M2 | M1 и пересчёт выборки: объём завершённого процесса добавляется к наблюдению, точка цензурирована, нижняя граница удерживается 60 с |
| M3 | пик за интервал (`memory.peak`) вместо мгновенного значения; пик, упёршийся в выделенный объём, — цензурированное наблюдение |
| M4 | M3 и запас по квантили 0,9 разности «пик − мгновенное» и ограничение интервала |
| M5 | M2 и агент событий в гостевой ОС (порог свободной ОП и скорости роста) с внеплановыми точками |

## Показатели

- отказов на задание (с 95 %-ным бутстреп-интервалом);
- обнаружено отказов и задержка обнаружения;
- заданий с отказом и невыполненных (пять неудачных попыток);
- среднее время выполнения задания;
- точек мониторинга в минуту;
- средний избыток выделенной ОП над занятой.
